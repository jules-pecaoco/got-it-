This follow-up implements the seven findings in the [audit](../archive/RELIABILITY_PERFORMANCE_AUDIT_2026-11-08.md). All verification used fictional records and disposable workspaces. Application deployment and classroom records were left under operator control.

## Operating and verification notes

- Run `npm run check`, `npm run verify:coding`, `npm run verify:web`, and `npm run verify:recovery` before deploying the change. The recovery command deliberately exits the owner of one short-lived disposable workspace and observes its automatic removal.
- Use `npm run test:load:mixed` for a simulated mixed workload. For explicit real execution and student count across shells, use the command in the [test plan](TEST_PLAN.md#current-load-rehearsals).
- Each mixed workload runs at most eight student workflows simultaneously, matching the default terminal limit. The 80-slot replacement regression separately establishes the preview capacity boundary. A full-duration, 80-student real-Docker classroom run remains a deployment rehearsal.
- New containers carry `gotit.owner` and `gotit.expires` labels. Keep `EXECUTION_INSTANCE_ID` stable across restarts if configured. Expired cleanup is scoped to that installation; operators should inspect legacy unlabeled containers separately during upgrade.
- Schema initialization adds `web_checkpoints`. Its foreign key removes checkpoints when their owning session is deleted. Preserve the usual verified backup before deployment or rollback.
- Authenticated `/api/instructor/system` now includes preview counts/backlog and checkpoint/settlement status. Monitor those alongside existing queue and request metrics.
- A forced host failure can lose changes made since the last successful checkpoint. Preview POST success now includes its persisted database snapshot; other PHP database mutations receive periodic and save/export/replacement/shutdown checkpoints. Off-host copies and restore drills address host/disk loss.
- Institutional identity policy, off-host backup destinations, retention, network routing and full-duration capacity targets remain operator deployment decisions described in the existing release gates.

Local logs are in `output/resolution-*.log`; that directory is ignored by Git. The maintained regressions are in `tests/reliability.test.mjs`, and the reproducible real execution checks are in `scripts/verify-workspace-recovery.mts` and `scripts/load-test-mixed.mts`.
